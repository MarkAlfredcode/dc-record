Do NOT force a CSS `min-width` on them and rely on a `overflow-x:auto` wrapper div to scroll it — that combination is broken in practice: Outlook desktop's Word rendering engine ignores `min-width` entirely and collapses the table to whatever width its container has (columns come out visibly cramped/compressed), while several real mobile mail clients don't reliably contain a scrolling div nested inside a table cell, so the forced min-width blows out the whole message's width instead of just scrolling that one table (2026-08-30: confirmed live — this exact combination produced "compressed on desktop, super wide on mobile" as reported by the reader). Fix: give every data table `width="100%"` with no `min-width` at all, and do NOT set `white-space:nowrap` on any cell — let column text wrap onto 2-3 lines on a narrow screen instead of forcing a fixed column width. This makes the table always fit 100% of whatever container width it's in (mobile or desktop, any client) with no dependency on min-width or overflow-x support. Columns will look tighter on a phone than a wide desktop screen, and that's fine — narrower/wrapped is the acceptable tradeoff, an uncontained horizontal blowout is not. Don't drop table columns to fight this either — full data stays, it just wraps.

Every background/text color anywhere in the document should still be set explicitly inline too (not just relying on the `<style>` block, which some clients strip) — that inline-everywhere approach is itself part of what keeps Gmail's auto-dark-mode from repainting things.
